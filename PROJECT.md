# BladeLoop — Project Reference & Development Workflow

> **Purpose:** This is the canonical reference for project planning and
> delivery. Keep it current as decisions, requirements, tools, and project
> scope change.

**Status:** Active
**Last updated:** 2026-10-07

BladeLoop is a React Native arcade side-scroller: a corridor of blades scrolls
past from the right, gravity pulls the ball toward the floor, a tap throws it
back up, and a drag nudges it forward or back along the run. Twenty authored
levels and an endless road past them, a global leaderboard and a coin economy
sit around that loop. There are no ads.

## 2. Standard Documents Required for Every New Project

These four exist for BladeLoop and are the documents to create before
implementation begins on any new project:

1. **[PR Document — Professional Requirements](docs/PR.md)**
   Project purpose, problem statement, target users, goals, scope,
   assumptions, constraints, stakeholders, and success criteria.
2. **[ER Document — Entity-Relationship Diagram](docs/ER.md)**
   Entities, attributes, primary/foreign keys, relationships, cardinalities,
   and relevant data constraints, with a Mermaid source diagram.
3. **[Functional Requirements Document](docs/FUNCTIONAL-REQUIREMENTS.md)**
   Features and user flows, inputs/outputs, validation, permissions,
   error/empty/loading states, and acceptance criteria.

## 4. Change Management — Keep This File Updated

Whenever a project decision, requirement, tool, architecture, scope, or
workflow changes:

1. Update the relevant section in this file.
2. Add a dated entry to the Change Log below.
3. Update affected project documents and checklists so they remain consistent.
4. Mark unresolved assumptions as **Clarification needed** rather than
   inventing details.

Practical mapping for this repo:

| A change to… | Also update |
| --- | --- |
| Scope, audience, success criteria | `docs/PR.md` |
| Stored fields, Firestore shape, storage keys | `docs/ER.md`, `firestore.rules` |
| A screen, a control, a game rule | `docs/FUNCTIONAL-REQUIREMENTS.md` |
